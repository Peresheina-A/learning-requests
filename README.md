# AI-buddy — помощник стажёра

Локальный учебный прототип: план адаптации, материалы, пять функций ИИ и отдельная имитация корпоративного сервиса. Используйте только тестовые данные. Прототип рассчитан на одного стажёра; общие статусы в SQLite не подходят для многопользовательского размещения.

## Запуск на Windows

Нужны Python 3.11 и Ollama с моделью `qwen3:1.7b`. Из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
ollama pull qwen3:1.7b
```

Создание окружения и скачивание модели нужны только при первой установке. Перед запуском проверьте, не работают ли сервисы:

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8000,8001,11434 -ErrorAction SilentlyContinue
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:11434/api/tags
```

Порт 8000 — AI-buddy, 8001 — корпоративный сервис, 11434 — Ollama. У корпоративного сервиса нет `/health`. Не запускайте второй экземпляр на занятом порту. Если Ollama не работает, запустите приложение Ollama либо `ollama serve` в отдельном терминале. Затем:

```powershell
.\.venv\Scripts\python.exe run_services.py
```

Откройте http://127.0.0.1:8000/ . Остановка обоих сервисов — Ctrl+C в терминале запуска. Запуск одного `uvicorn app:app` недостаточен для входа и корпоративных сценариев.

## Тестовый вход

- Роль: **Стажёр**.
- Логин: `Anastasia`, пароль: `1234` — только локальная демонстрационная учётная запись.
- Профиль: Перешеина Анастасия Владиславовна, аналитик данных.
- Стажировка: **09.11.2026–09.12.2026**.

Вход руководителя и куратора не подключён. Имя, должность и даты приходят из корпоративного сервиса. У существующей базы дата не меняется автоматически при обновлении исходников; новая база получает дату из `corporate-service/profiles.py`. Для основной локальной базы дата исправлена отдельно, без удаления заявок.

## Порядок ручной проверки

1. Проверьте неверный пароль, вход стажёра, профиль через меню «+», выход и повторный вход.
2. Проверьте этапы и сроки относительно даты старта: 16.11.2026 — день 8, вторая неделя. Первая неделя заканчивается 15.11, вторая — 22.11; последний этап — 09.12.
3. Откройте чаты, доступы, дату знакомства, рабочие инструменты и материалы. Самоподтверждение означает только отметку стажёра. После смены статуса обновите страницу.
4. В задачах целей и встречи отправьте заявку, обновите страницу во время ожидания, откройте результат и уведомления. Сервис имитирует ответ примерно через пять секунд при опросе. Встреча «готово» означает назначение, а не проведение. Ссылки на `example.com` являются тестовыми.
5. Попробуйте функции ИИ через меню «+» и свободный запрос: ответы по документам, подбор задачи, следующие шаги, объяснение и черновик наставнику. Проверяйте цитаты и содержание; ответы модели могут быть неверными. Черновик не отправляет сообщения.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

HTTP-тесты запускают оба сервиса на свободных портах, используют временные базы и настоящий вход. Основные базы не затрагиваются. После перезапуска тестового сервера выполняется новый вход: сессии хранятся в памяти. Автотесты `llm.py` подменяют ответы модели и не доказывают качество пяти ИИ-функций.

Дополнительная проверка настоящей модели для извлечения полей заявки:

```powershell
.\.venv\Scripts\python.exe check_llm.py
```

Она не создаёт заявки и не проверяет все функции AI-buddy. Покрытие более 80% не подтверждено; воспроизводимый отчёт покрытия и SDD-спецификации пока не приложены.

## Устройство и данные

Браузер → FastAPI (`app.py`) → `corporate_gateway.py` → отдельный FastAPI (`corporate-service/corporate_app.py`). `onboarding.py` рассчитывает календарь; `materials.py` хранит материалы. Пять ИИ-функций реализованы в `ai_features.py`, запросы направляются настоящей Ollama. Браузер использует JavaScript, встроенный в `index.html`; соседние файлы `*-ui.js` содержат исходники соответствующих блоков.

- `requests.db` — заявки, статусы адаптации, подтверждения, уведомления и материалы.
- `corporate-service/corporate.db` — тестовый профиль, заявки на цели и встречи, отзывы.
- Базы, `.venv`, локальные `.env` и результаты QA не включаются в Git. Не удаляйте базы для обновления проекта: потеряется сохранённый прогресс.
- Прикрепление новых материалов через интерфейс пока отключено до подключения аккаунта руководителя.

## Конфигурация

Переменные задаются в окружении процесса; `.env` автоматически не читается. Пример без секретов — `.env.example`.

| Переменная | По умолчанию |
|---|---|
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` |
| `OLLAMA_MODEL` | `qwen3:1.7b` |
| `CORPORATE_SERVICE_URL` | `http://127.0.0.1:8001` |
| `CORPORATE_SERVICE_KEY` | локальный демонстрационный ключ из кода; одинаковый у двух сервисов |
| `LEARNING_REQUESTS_DB` | `requests.db` рядом с `storage.py` |
| `CORPORATE_DB` | `corporate-service/corporate.db` |

Облачный API-ключ для Ollama не требуется. При изменении URL текст будет передаваться по новому адресу. Не публикуйте прототип с реальными персональными данными. Docker в текущий объём изменений не входит.
