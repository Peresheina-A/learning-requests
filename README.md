# Учебные заявки

Небольшой учебный проект для подготовки к AI-buddy. Это не финальный MVP:
продуктовые требования к нему согласуются отдельно.

Пользователь создаёт тестовую заявку, получает номер и статус `created`,
а затем может найти заявку по номеру. Реальный доступ к инструментам не выдаётся.

## Устройство

Браузер → HTTP/JSON → FastAPI → модуль `storage.py` → SQLite.

- `index.html` — интерфейс, оформление и JavaScript с вызовами API.
- `app.py` — обработчики HTTP, проверка данных, выдача страницы.
- `storage.py` — имитация сервиса заявок и сохранение данных.
- `llm.py` — извлечение полей через локальную Ollama, без сохранения заявки.
- `tests/test_api.py` — интеграционные тесты через настоящий локальный сервер.
- `requirements.txt` — версии основных зависимостей.

## Запуск на Windows

Нужен Python 3.11. Откройте терминал в папке проекта.
При первом запуске создайте окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если окружение уже создано, повторять первую команду не нужно.
Запуск сервера:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --reload
```

- Приложение: http://127.0.0.1:8000/
- Документация API: http://127.0.0.1:8000/docs
- Остановка: Ctrl+C в терминале сервера.

Открывайте страницу через сервер, а не через `file://`: интерфейсу нужен backend.
Если порт 8000 занят, остановите предыдущий сервер или добавьте `--port 8001`
и откройте страницу с новым номером порта.

## Проверка

В отдельном терминале:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

Тесты сами запускают серверы на свободных портах и используют временные базы.
Рабочие заявки не затрагиваются. Проверяются создание, чтение, отклонение
ошибочных данных, отсутствие заявки и сохранность после перезапуска.
Действия пользователя в браузере этими тестами не проверяются.

## API

| Метод | Адрес | Результат |
|---|---|---|
| GET | `/health` | Ответ `200`, если приложение работает |
| POST | `/api/requests` | Сохраняет заявку, возвращает `201`, номер и статус |
| GET | `/api/requests/{id}` | Возвращает заявку или `404` |
| POST | `/api/suggestions` | Предлагает поля по тексту, без создания заявки |

Тело POST: `{"tool": "Учебная Jira", "reason": "Для первой задачи"}`.
Оба поля обязательны. Пробелы по краям удаляются; пустой текст отклоняется с `422`.

## Данные и ограничения

База `requests.db` создаётся рядом с `storage.py` при запуске приложения.
Переменная `LEARNING_REQUESTS_DB` позволяет выбрать другой файл (используется тестами).
Окружение, локальные базы и `.env` исключены из Git.

В прототипе пока нет авторизации, ролей, согласования или выдачи доступа.
Используйте только синтетические данные и локальный запуск.
Повторный POST создаёт новую заявку: защита от дублей между запросами не реализована.
Покрытие кода пока не измерено.

## Локальная модель (необязательно)

Установите Ollama с https://ollama.com/download/windows и скачайте модель:

```powershell
ollama pull qwen3:1.7b
ollama list
```

Ollama должна быть запущена (по умолчанию слушает `127.0.0.1:11434`).
Если API не отвечает, запустите `ollama serve` в отдельном терминале.
Если порт уже занят Ollama, второй сервер запускать не нужно.
Затем запустите наше приложение обычной командой и откройте главную страницу.
Введите текст и нажмите «Заполнить с помощью ИИ». Проверьте предложенные поля;
только кнопка «Отправить заявку» сохраняет запись.

Настройки backend по умолчанию, которые можно задать в PowerShell перед запуском:

```powershell
$env:OLLAMA_BASE_URL = "http://127.0.0.1:11434"
$env:OLLAMA_MODEL = "qwen3:1.7b"
```

API-ключ и облачный сервис не используются. Текст передаётся локальной Ollama;
при изменении адреса сервера текст будет отправляться по настроенному адресу.
Файл `.env` автоматически не читается. Пример переменных — в `.env.example`.

Модель получает JSON-схему, работает с `think: false` и коротким контекстом
2048 токенов. Ожидание ответа ограничено 90 секундами. Пустые неизвестные поля
можно заполнить вручную. Проверка схемы не гарантирует правильность смысла:
маленькая модель может выдумать или неверно извлечь сведения.
При ошибке ИИ обычное создание заявки остаётся доступным.
Первый вызов может быть медленнее из-за загрузки модели в память.

Автотесты ИИ используют подменённые ответы и не требуют скачанной модели.
Они проверяют контракт и ошибки, но не качество реальных ответов модели.

## Автоматическая проверка

`.github/workflows/tests.yml` запускает установку зависимостей, `pip check`
и тесты на Python 3.11 в Windows и Ubuntu при push и pull request.
Для ручного запуска предусмотрен `workflow_dispatch`.
Workflow начнёт работать после загрузки проекта в GitHub при включённых Actions.
Он проверяет проект, но не публикует приложение.
