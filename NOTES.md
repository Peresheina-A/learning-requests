# Мои заметки по учебному проекту

Краткая шпаргалка для работы. Подробная инструкция и настройки — в [README.md](README.md).
Это учебный прототип; требования финального AI-buddy согласуем отдельно с Дашей.

## Запуск приложения

Открыть папку `learning-requests` в VS Code и её терминал:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --reload
```

- `.venv` — отдельное окружение Python для проекта.
- `-m uvicorn` — запустить сервер Uvicorn через этот Python.
- `app:app` — объект `app` из файла `app.py`.
- `--reload` — перезапускать сервер при изменении кода.
- Остановка сервера: **Ctrl+C** в его терминале.

Приложение: http://127.0.0.1:8000/

Документация API: http://127.0.0.1:8000/docs

Открывать сайт через сервер, а не двойным щелчком по `index.html`.

## Проверка проекта

В другом терминале той же папки:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`OK` означает, что запущенные проверки прошли. Это не гарантия отсутствия всех ошибок.
Тесты используют временные базы; рабочие заявки не затрагивают.
Ответы LLM в автотестах подменяются: смысл реальных ответов проверяем отдельно.

## Локальная модель

Используем Ollama и `qwen3:1.7b`. Модель уже скачана на этот ноутбук.

```powershell
ollama list
```

Показать скачанные модели.

```powershell
ollama run qwen3:1.7b
```

Открыть отдельный чат с моделью в терминале. Выход из чата: `/bye` после `>>>`.
Для работы сайта открытый терминальный чат не требуется, но API Ollama должен работать.
Если Ollama не запущена, см. раздел «Локальная модель» в README.

## Как устроено приложение

1. `index.html` показывает форму и отправляет HTTP-запросы через JavaScript `fetch()`.
2. `app.py` принимает запросы и проверяет данные.
3. `llm.py` запрашивает у Ollama предложение полей. Заявку не сохраняет.
4. Пользователь проверяет и исправляет предложение ИИ.
5. Кнопка «Отправить заявку» вызывает backend и `storage.py`.
6. SQLite сохраняет запись в `requests.db`; интерфейс показывает её номер и статус.

`created` означает «заявка сохранена», а не «доступ выдан».
Правильный JSON не гарантирует правильный смысл. ИИ может ошибаться.
У модели пока нет базы знаний команды и реальных регламентов Авито.

## Git: посмотреть и сохранить изменения

```powershell
git status
git diff
```

Показывают состав изменений и разницу в уже отслеживаемых файлах.
Для нового файла нужно отдельно открыть и прочитать его содержимое.

```powershell
git add NOTES.md
git diff --cached
git commit -m "Add personal project notes"
git push
```

Пример сохранения этой заметки: выбрать файл → проверить подготовленные изменения →
создать локальный коммит → отправить его на GitHub.
Для других изменений перечислить нужные файлы вместо `NOTES.md`.

```powershell
git log -5 --oneline
```

Показать последние пять коммитов. Commit — сохранённая точка истории;
push — отправка коммитов в удалённый репозиторий.
После push GitHub Actions запускает проверки; это не публикация работающего сайта.

Не добавлять в Git `.venv`, `requests.db`, `.env`, пароли и API-ключи.

## Следующая проверка качества ИИ

Ввести в поле ИИ: «Мне нужен доступ».
Ожидаем: неизвестные поля пустые, модель не придумывает инструмент или причину.
Если ответ неверный — записать исходный текст, ответ и ожидаемый результат.
